# 通过 SSH 隧道连接数据库

如果数据库管理员提供了可访问数据库的堡垒机，可通过 SSH 隧道连接。该功能需要 SqlKit 旗舰版。请准备 SSH 主机和数据库各自的登录信息。

## 为连接添加 SSH 配置档案

1. 在连接编辑器中打开一个[数据库连接](/zh/docs/sqlkit/connect-to-database)。在**基础**中填写最后一跳 SSH 主机所能访问的数据库地址、端口以及数据库凭据。例如 PostgreSQL 与堡垒机位于不同机器时，这里填写 PostgreSQL 的内网主机名。
2. 打开**高级 → SSH 隧道**，选择**添加配置档案…**或**新建配置档案**。
3. 新建档案时，填写堡垒机主机名、SSH 用户名以及端口（通常为 `22`），再选择密码、私钥或 SSH Agent 认证。保存后，该档案会加入当前连接。
4. 在连接编辑器中选择**测试连接**。通过后保存连接，在**查询**中确认已经连接到目标数据库。

## 使用多个堡垒机

从当前设备能访问的主机开始，按跳转顺序添加 SSH 配置档案。SqlKit 会通过最后一跳连接数据库。从这条连接移除某个档案后，仍可在其他连接中使用它。

## 排查隧道连接故障

| 现象 | 检查项 |
| --- | --- |
| SSH 配置档案测试超时 | 检查当前设备能否访问第一个堡垒机，是否需要接入组织的 VPN。 |
| 第一跳测试成功，但**测试连接**失败 | SSH 测试只检查第一跳。检查每台后续主机能否从上一跳访问，并确认最后一跳能访问**基础**选项卡中填写的数据库地址和端口。 |
| 数据库拒绝登录或证书校验失败 | 分别检查数据库凭据和 TLS 设置。使用隧道时仍需满足数据库的认证和证书要求。 |
| 应用提示尝试了直连 | 检查登录状态和订阅版本。社区版和未登录会话会跳过该连接已保存的 SSH 配置。 |

数据库自身的错误见[连接故障排查](/zh/docs/sqlkit/connect-to-database#troubleshoot-a-failed-connection)。
