# SSH 隧道、多跳堡垒机与代理支持

<DocsBadge variant="ultimate">旗舰版</DocsBadge>

当数据库位于私有 VPC、企业内网或一台/多台堡垒机（跳板机）之后时，可以通过 SqlKit 内置的 Rust SSH 客户端建立转发隧道。SqlKit 会在本机打开随机空闲的回环端口（`127.0.0.1`），将数据库流量经由单跳或多跳 SSH 链路转发到目标数据库。

<DocsFlowDiagram variant="ssh-tunnel" />

## 支持的隧道与代理方式

| 类型 | 支持状态 | 适用场景 |
| --- | --- | --- |
| SSH 隧道（单跳或多跳） | 支持（旗舰版） | 拥有跳板机、堡垒机或可访问数据库的服务器的 SSH 权限。 |
| 系统代理（`http://` HTTP CONNECT，第 0 跳） | 配合 SSH 支持（旗舰版） | 本机访问第一跳堡垒机必须经过操作系统配置的 HTTP CONNECT 代理；需至少挂载一个 SSH 跳板。 |
| 独立 SOCKS5 / HTTP 代理（不经 SSH） | 暂不支持 | SqlKit 目前不提供脱离 SSH 的独立数据库代理层。 |
| HTTP 隧道（服务端 Web 脚本） | 暂不支持 | SqlKit 不提供需部署到内网 Web 服务器的 HTTP/PHP 隧道脚本。 |
| 文件型数据库（SQLite、SQLCipher、DuckDB） | 仅本地文件 | 文件型引擎直接打开本机文件，不经过 SSH 传输层。 |

::: info AI 与下载使用的出站 HTTP 代理
**设置 → AI** 中按供应商配置的代理（`无`、`系统`、`手动`）仅作用于出站 HTTP 请求（例如调用大模型 API），不用于数据库连接驱动流量。
:::

## 创建可复用的 SSH 配置

在**连接管理**页面点击**添加 SSH 配置**即可维护全局共享的 SSH 配置，也可以在编辑任意数据库连接时从**高级 → SSH 隧道**点击 `+` 内联创建。同一份 SSH 配置可以被多个数据库连接复用，修改配置后所有引用它的连接都会同步生效。

| 字段 | 说明 |
| --- | --- |
| 配置名称 | 在隧道链路和选择器中显示的名称 |
| SSH 主机 | 堡垒机域名、IP 地址，或 `~/.ssh/config` 中定义的 `Host` 别名。连接时 SqlKit 会自动读取 `~/.ssh/config` 补全未填写或保持默认值的 `HostName`、`Port`、`User` 与 `IdentityFile`（跳过通配符和 `Include` 指令）。 |
| SSH 端口 | 堡垒机 SSH 端口（默认 `22`） |
| 用户名 | 堡垒机 SSH 登录账号 |
| 认证方式 | 支持**密码**、**私钥文件**（可浏览本机文件并填写可选口令 Passphrase）或 **SSH Agent**（自动使用 `$SSH_AUTH_SOCK`、自定义 Socket 路径或 Windows 下的 Pageant）。连接时会先探测 SSH `none` 认证，兼容允许无凭据登录的特殊网关。 |

每一跳 SSH 连接默认使用内置的 `10s` 连接超时和 `30s` 保活心跳（Keepalive），防止空闲隧道被 NAT 或防火墙切断。

在 SSH 配置弹窗中点击**测试连接**，可先单独验证该堡垒机的连通性与身份认证，再将其挂载到数据库连接上。

## 挂载多跳链路与可选系统代理

<DocsSteps>

### 按“最后一跳”视角填写数据库地址

在连接表单的**基础**选项卡中，填写最后一跳堡垒机所能访问到的数据库主机和端口。若 PostgreSQL 运行在内网 RDS（`prod-db.internal:5432`）或就运行在堡垒机本机（`127.0.0.1:5432`），这里应填写内网地址，不要填堡垒机公网 IP。

### 添加一个或多个 SSH 配置

切换到**高级 → SSH 隧道**，从下拉选择器添加已保存的 SSH 配置，或点击 `+` 新建配置。需要经过多台跳板机时（如企业边界跳板机到 VPC 堡垒机再到内网库），按顺序依次添加各跳 SSH 配置。

### 可选：将操作系统代理挂载为第 0 跳

当操作系统配置了 HTTP 代理时，SqlKit 会自动检测（遵循 `NO_PROXY` 和系统代理例外列表），并在 **SSH 隧道**面板中显示**系统代理**提示条。点击**添加**即可将其固定为第 `0` 跳，放在第一跳堡垒机之前。

代理地址在连接时动态从操作系统解析，不会持久化写入连接配置。系统代理仅支持 `http://` HTTP CONNECT 代理，且需要配合至少一个 SSH 跳板使用。

### 拖拽调整顺序并核对链路预览

在列表中拖动排序手柄（或点击上下移按钮）即可调整跳板顺序。SqlKit 会实时显示路径预览（`System Proxy → Hop 1 → Hop 2 → Database`），方便在测试前核对完整转发链路。

### 测试并保存连接

点击 **SSH 隧道**标题栏的测试图标可校验第一跳连通性；点击数据库连接弹窗底部的**测试连接**，SqlKit 会建立整条 SSH 链路、绑定本地回环端口，并端到端校验数据库登录与 TLS 配置。

</DocsSteps>

::: tip 复用、解绑与旧版内联隧道转换
从某个数据库连接的链路中移除 SSH 配置只会解除关联，不会删除该共享配置，其他连接仍可继续使用。

如果旧连接使用的是仅限单连接的内联 SSH 配置，可以继续直接编辑（编辑弹窗支持从 `~/.ssh/config` 导入主机条目），也可以点击**转为配置**将其迁移为可复用 SSH 配置，以便参与多跳编排。
:::

## 隧道运行机制与当前限制

- 本地转发端口始终绑定在 `127.0.0.1` 的系统随机空闲端口上；界面暂不支持指定固定本地端口或开启 `0.0.0.0` 局域网监听。
- 多个数据库连接若使用完全相同的 SSH 跳板链路与目标 `host:port`，会自动复用同一条活跃隧道。
- 当前界面默认以宽松主机密钥模式建立连接，暂未提供交互式 `known_hosts` 指纹确认或取消固定界面。请确认堡垒机地址准确，并配合私钥认证与私有网络访问控制使用。

## 社区版降级行为

如果曾在旗舰版配置过 SSH 隧道，之后在未登录或切换回社区版时打开 SqlKit，已保存的 SSH 配置和链路会保留，不会被删除。连接数据库时会跳过 SSH 隧道，并提示当前正在尝试直连数据库。

## 排查 SSH 隧道故障

| 现象 | 检查项 |
| --- | --- |
| SSH 配置测试超时 | 确认本机能访问第一跳堡垒机及端口，检查 VPN 状态；若需经公司 HTTP CONNECT 代理出网，在数据库连接中挂载**系统代理**。 |
| 系统代理显示“未检测到”或连接失败 | 确认系统网络设置中已启用 `http://` 代理，且第一跳堡垒机不在 `NO_PROXY` 或系统代理例外列表中。第 0 跳不支持 SOCKS 代理 URL；若连接时检测不到适用代理，SqlKit 会回退为直连第一跳。 |
| 第一跳通过，但数据库“测试连接”失败 | 配置弹窗测试与标题栏测试按钮只校验第一跳。请确认上一跳能够访问下一跳，且最后一跳能解析并连通**基础**选项卡中的数据库地址和端口（并确认堡垒机 `sshd_config` 已开启 `AllowTcpForwarding yes`）。 |
| `~/.ssh/config` 别名未生效 | 确认配置块使用精确主机别名（跳过 `*` 等通配符及 `Include` 指令），且当前用户对 `~/.ssh/config` 有读取权限。 |
| SSH Agent 认证失败 | 确认私钥已加载（macOS/Linux 执行 `ssh-add -l`，Windows 确认 Pageant 正在运行）；如未用默认 `$SSH_AUTH_SOCK`，核对自定义 Socket 路径。 |
| 隧道下出现 TLS 主机名不匹配 | SSH 隧道通过 `127.0.0.1` 转发 TCP 流量，数据库仍会出示自身 TLS 证书。确认**基础**页主机名与证书 SAN/CN 一致；若通过内网 IP 访问，可配合 CA 证书改用 `verify-ca`。 |
| 提示正在尝试直连数据库 | 打开**设置 → 通用 → 账号与方案**确认旗舰版状态有效，并确认目标不是本地文件型数据库（SQLite、SQLCipher、DuckDB）。 |
