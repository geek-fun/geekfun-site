# SSH 隧道与多跳堡垒机

<DocsBadge variant="ultimate">旗舰版</DocsBadge>

当数据库部署在私有 VPC、企业内网或一台/多台堡垒机（跳板机）之后时，可通过 SqlKit 的 **SSH 隧道**建立安全加密转发。SqlKit 支持**全局可复用的 SSH 配置**，同一台堡垒机可以挂载到任意多个数据库连接上，也可以串联成多跳链路。

```text
本机 ──► [可选：系统 HTTP 代理] ──► 堡垒机 1 (SSH) ──► 堡垒机 2 (SSH) ──► 内网数据库
```

## 创建可复用的 SSH 配置

你可以在**连接管理**页面集中维护 SSH 配置，或在编辑任意数据库连接时从**高级 → SSH 隧道 → 新建配置**内联创建：

| 字段 | 说明 |
| --- | --- |
| **配置名称** | 在隧道链路与选择器中显示的易读名称 |
| **主机与端口** | 堡垒机地址与 SSH 端口（默认 `22`）。SqlKit 支持读取 `~/.ssh/config` 中的主机列表辅助选择。 |
| **用户名** | 堡垒机 SSH 登录账号 |
| **认证方式** | **密码**、**私钥文件**（可选私钥口令 Passphrase），或 **SSH Agent**（自动使用 `$SSH_AUTH_SOCK`、自定义 Socket 路径，或 Windows 下的 **Pageant**） |
| **连接超时** | 等待 SSH 握手的超时时间（默认 `10s`） |
| **保活间隔（Keepalive）** | 心跳包间隔，防止空闲隧道被 NAT 或防火墙切断（默认 `30s`） |
| **使用系统代理** | 通过操作系统检测到的 HTTP CONNECT 代理发起第一跳 SSH 连接 |

在 SSH 配置弹窗中点击**测试 SSH 连接**，即可独立验证该堡垒机的连通性、身份认证与主机密钥信任状态。

## 挂载单跳或多跳堡垒机链

<DocsSteps>

### 按“最后一跳”的视角填写数据库地址

在连接表单的**基础**选项卡中，填写**最后一跳堡垒机所看到的数据库主机与端口**。例如，若 PostgreSQL 运行在内网 RDS（`prod-db.internal:5432`）或就运行在堡垒机本机（`127.0.0.1:5432`），此处应填写内网地址，而非堡垒机公网 IP。

### 添加一个或多个 SSH 配置

切换到**高级 → SSH 隧道**，点击**添加配置**。如果需要穿越多层跳板机（如企业边界跳板机 → VPC 堡垒机 → 内网库），按先后顺序依次添加各跳 SSH 配置。

### 拖拽调整顺序并核对实时链路预览

在列表中直接拖拽各跳顺序即可调整转发路径。SqlKit 会实时渲染可视化链路面包屑（`System Proxy → Hop 1 → Hop 2 → Database`），方便在测试前核对完整路径。

### 测试并保存连接

点击数据库连接弹窗中的**测试连接**。SqlKit 会按序建立整条 SSH 通道、绑定本地转发端口，并端到端校验数据库账号与 TLS 配置。

</DocsSteps>

::: tip 复用与解绑机制
从某个数据库连接的链路中移除 SSH 配置只会解除关联，不会删除该 SSH 配置，其他连接仍可继续复用。
:::

## 主机密钥校验（`known_hosts`）

为防范中间人攻击，SqlKit 对每台堡垒机执行主机密钥校验与固定（pinning）：

- 首次连接堡垒机时，记录其主机密钥指纹。
- 若后续堡垒机主机密钥发生意外变更（例如实例重建或密钥轮换），SqlKit 会拦截连接并发出明确告警，绝不静默接受变更。
- 与运维团队核实确认后，可在 SSH 设置中取消固定（unpin）旧主机指纹以信任新密钥。

## 社区版降级行为说明

如果你曾在旗舰版配置过 SSH 隧道，后续在未登录或切换回**社区版**状态下打开 SqlKit：

- SqlKit 会**完整保留**已保存的 SSH 配置与链路，不会删除任何配置。
- 连接尝试会**跳过** SSH 隧道，并给出明确提示说明当前正尝试直连数据库。

## 排查 SSH 隧道故障

| 现象 | 检查项 |
| --- | --- |
| **SSH 配置测试超时** | 确认本机能否直达第一跳堡垒机及端口，检查企业 VPN 状态；若需经由公司 HTTP 代理出网，请开启**使用系统代理**。 |
| **第一跳通过，但数据库“测试连接”失败** | 单独测试 SSH 仅校验该跳本身。请确认上一跳能够访问下一跳，且**最后一跳**能解析并连通**基础**选项卡中填写的数据库地址和端口（同时确认堡垒机 `sshd_config` 已开启 `AllowTcpForwarding yes`）。 |
| **SSH Agent 认证失败** | 确认私钥已加载（macOS/Linux 执行 `ssh-add -l`，Windows 确认 Pageant 正在运行），若未使用默认 `$SSH_AUTH_SOCK` 请核对自定义 Socket 路径。 |
| **主机密钥校验失败** | 堡垒机指纹与已固定记录不一致。向运维核实后，先取消固定旧指纹再重连。 |
| **隧道下出现 TLS 主机名不匹配** | SSH 隧道仅转发 TCP 流量，数据库依然会出示自身 TLS 证书。请确认**基础**页主机名与证书 SAN/CN 一致；若通过内网 IP 访问，可配合 CA 证书改用 `verify-ca`。 |
| **提示正在尝试直连数据库** | 打开**设置 → 通用 → 账号与方案**确认旗舰版状态有效；未登录或社区版会话会自动跳过 SSH 隧道。 |
