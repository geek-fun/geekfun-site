# 配置 SqlKit AI 权限

应用内助手或外部 MCP 客户端请求访问数据库时，SqlKit 会检查连接的 AI 权限。修改默认权限和单连接权限需要旗舰版。

## 设置默认权限与连接权限 {#connection-permissions}

1. 打开**设置 → MCP 桥接 → 默认 AI 权限**。若只需要查看结构和执行读查询，选择**读取**并保存。即使从未修改过设置，也可以先查看当前权限。
2. 在**连接管理**中编辑已保存的连接，打开**高级 → AI 权限**。连接可继承默认设置，也可使用**自定义**逐项选择允许、拒绝或使用默认权限。
3. 在 **Data Studio** 中选中已添加的数据源，查看会话权限。会话可以在连接权限的基础上进一步限制访问。

| 访问级别 | AI 可以做什么 |
| --- | --- |
| **禁止访问** | 禁止数据与管理操作。 |
| **读取** | 查看结构和读取数据。 |
| **读取和修改数据** | 读取、新增、更新和删除数据。 |
| **完全访问** | 操作数据、修改结构及执行管理操作。 |
| **自定义** | 分别设置读取、新增、更新、删除和管理权限。 |

## 了解询问、自动与客户端确认 {#approvals}

在应用内会话中，**询问**模式会对已获权限的高风险操作请求确认，**自动**模式可以直接执行其中部分操作。破坏性操作在两种模式下均需确认，除非已有匹配的确认规则。切换模式不会开放连接或会话拒绝的操作。

外部 MCP 客户端决定何时弹出确认提示，SqlKit 则在执行前检查连接权限。两种情况下，数据库本身仍会检查连接账号的权限。

## 检查被阻止的操作 {#blocked-actions}

1. 在 Data Studio 的受阻消息上选择**检查权限**，确认涉及的连接和被拒绝的操作。
2. 如果确实需要开放该操作，检查连接和会话限制，优先在**自定义**模式下只允许所需操作。
3. 保存后选择**重试请求**，SqlKit 会重新检查当前权限。

模型可能收到工具返回的结构和数据。使用外部 MCP 客户端时，由客户端决定哪些结果会发给其模型。若某个连接不应进入 AI 工作流，将其设为**禁止访问**。
